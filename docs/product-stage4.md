# Этап 4. Продукт: очки за укорачивание, уведомления, публичные страницы

Что изменилось в игре и что нужно сделать один раз при деплое.

---

## 1) Очки за укорачивание решения

До этого очки давали один раз — за первое решение задачи, хотя `/rules` и сайдбар
рейтинга обещали очки и за улучшения. Теперь начисление совпадает с обещанным:

| За что | Очки |
| --- | --- |
| Первое решение Bronze / Silver / Gold | +10 / +20 / +30 |
| Улучшение своего рекорда на 1–3 символа | +5 |
| Улучшение на 4–9 символов | +10 |
| Улучшение на 10+ символов | +20 |
| Первый выход на #1 по задаче | +25 (один раз на задачу) |

Правила живут в одном месте: [`src/lib/points.ts`](../src/lib/points.ts).

Защита от накрутки:

- сумма очков за улучшения в одной задаче ограничена: 20 (Bronze), 40 (Silver),
  60 (Gold) — иначе можно отправить раздутое решение и срезать его по одному символу;
- бонус за первое место даётся один раз на задачу (`best_submissions.first_place_awarded`),
  поэтому «качать» его, отдавая и забирая рекорд, нельзя.

Что видит игрок после зачтённой отправки: `+N очков`, строку «было 47, короче на 9»
и расшифровку начисления.

## 2) Уведомление «твой рекорд побили»

- В шапке появился колокольчик с числом непрочитанных (только для авторизованных).
- Уведомление создаётся в той же транзакции, что и отправка решения: когда кто-то
  забирает первое место по задаче, бывшему лидеру приходит запись
  `notifications(type = 'record_beaten')`.
- Если непрочитанное уведомление по этой задаче уже есть — оно обновляется, а не
  плодится: серия улучшений одного игрока не превращается в спам.
- Читается при открытии списка: `POST /api/notifications/read`.

## 3) Цель по длине

Цифры показываем, код решений — нет:

- на странице задачи: «Лучшее решение — N символов», цель для топ-3, свой рекорд,
  своё место и сколько символов осталось срезать до места выше;
- на главной в карточке рекомендуемой задачи;
- в списке задач (`Лучший: N`).

## 5) Соревнования: подсчёт результатов

Раньше `competition_entries` не заполнялась никогда — лидерборд соревнования всегда
был пустым. Теперь:

- после каждой зачтённой отправки пересчитывается результат участника во всех
  соревнованиях, которые идут в этот момент и содержат задачу
  ([`src/lib/competitions.ts`](../src/lib/competitions.ts));
- в зачёт идут только PASS-попытки внутри окна соревнования (`startsAt..endsAt`),
  по каждой задаче берётся самое короткое решение;
- сортировка: больше решённых задач → меньше сумма длин → кто раньше прислал;
- на странице соревнования видно своё место, свои длины по задачам и правила подсчёта;
- у соревнований появилось состояние «СКОРО» (старт в будущем).

## 6) Публичная страница участника и картинка для Telegram

- `/u/<ник>` (или `/u/<id>`, если ника нет) — публичная страница: очки, решённые
  задачи, первые места, срезанные символы, прогресс по задачам. Кода решений там нет.
- `/u/<ник>/opengraph-image` — PNG 1200×630 с результатами. Эта же картинка уходит в
  превью ссылки в Telegram (`og:image` подставляется автоматически) и её можно скачать
  со страницы.
- Ссылки на публичные страницы есть в рейтинге, в лидербордах задач, в списке последних
  решений и в меню пользователя («Моя страница»).
- Публичные страницы попадают в `sitemap.xml` (до 500 участников с очками).

Шрифты для картинки лежат в `public/fonts/JetBrainsMono-*.ttf` (OFL, лицензия рядом):
`next/og` приносит с собой только латиницу, без этих файлов кириллица стала бы
пустыми квадратами. `deploy-standalone.sh` уже копирует `public/` в standalone-сборку.
Если шрифт не прочитается, картинка всё равно отдаётся — просто дефолтным шрифтом.

## 7) Что сделать один раз при деплое

Схему применяет обычный `npm run db:push` (он уже в деплой-скрипте). После этого —
два разовых бэкфилла:

```bash
npm run db:progress:backfill
npm run db:competitions:backfill
```

Первый восстанавливает по истории попыток `first_length` (с чего начинали) и
`improve_count`, а текущим лидерам задач ставит `first_place_awarded = true`, чтобы им
не начислился бонус +25 за место, занятое до появления правила. Очки задним числом он
**не** выдаёт, только печатает, сколько получилось бы. Если хотите их выдать:

```bash
RETRO_POINTS=true npm run db:progress:backfill
```

Второй пересчитывает результаты всех соревнований из истории попыток — без него
лидерборды прошедших соревнований останутся пустыми.

Оба скрипта идемпотентны: повторный запуск ничего не портит (с `RETRO_POINTS=true`
очки тоже не удваиваются — они считаются от уже начисленных `improve_points`).

## 7.1) Проверки без базы

```bash
npm run check:rules
```

Прогоняет начисление очков (включая лимит на задачу и защиту от накрутки мелкими
шагами), тексты уведомлений и сортировку лидерборда соревнования. Полезно запускать
после любой правки [`src/lib/points.ts`](../src/lib/points.ts).

`npm run ops:smoke` дополнительно проверяет, что `/api/notifications` закрыт без
сессии и что картинка `/u/<ник>/opengraph-image` реально рендерится.

## 8) Изменения в схеме БД

`best_submissions`:

| Поле | Зачем |
| --- | --- |
| `first_length` | длина первого зачтённого решения — «было 47» |
| `improve_count` | сколько раз игрок укорачивал решение |
| `improve_points` | сколько очков за улучшения уже начислено (для лимита) |
| `first_place_awarded` | бонус за #1 по задаче уже выдан |

Новая таблица `notifications`: `user_id`, `type`, `task_id`, `payload_json`, `read_at`.
