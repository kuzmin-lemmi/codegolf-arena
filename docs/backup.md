# Резервные копии и восстановление

Простая инструкция на случай «всё сломалось». Рассчитана на то, что читать её
будут в панике, поэтому команды можно копировать как есть.

## Что мы защищаем

В базе лежит то, что нельзя восстановить никаким другим способом:
пользователи, их решения, рекорды и очки. Задачи ещё можно перезалить из файла
`codegolf_tasks.json`, а результаты участников — нет.

## Где что лежит

| Что | Где |
|---|---|
| Копии базы | `/home/deploy/backups/codegolf-ГГГГММДД-ЧЧММСС.dump` |
| Аварийные снимки (перед восстановлением) | `/home/deploy/backups/pre-restore-*.dump` |
| Настройки сервера | `/home/deploy/codegolf-arena/.env` — **в git не хранится** |
| Копии вне сервера | S3-бакет, папка `codegolf/`, файлы `*.dump.gpg` — зашифрованы |
| Настройки хранилища и пароль шифрования | `/home/deploy/.config/codegolf/offsite.env` + менеджер паролей |
| Расписание копий | systemd-таймер `codegolf-backup.timer`, ежедневно в 03:30 |

На сервере копии хранятся 14 дней, но не меньше трёх последних штук в любом
случае. В хранилище — 30 дней.

---

## Ежедневные действия — никаких

Копии снимаются сами. Раз в месяц полезно заглянуть:

```bash
systemctl list-timers codegolf-backup.timer
ls -lh /home/deploy/backups/ | tail -5
```

---

## Снять копию прямо сейчас

Перед любым рискованным изменением (обновление, миграция, правка данных):

```bash
cd /home/deploy/codegolf-arena && bash scripts/backup-db.sh
```

## Убедиться, что копия рабочая

Это главная проверка. Копия, из которой нельзя восстановиться, — не копия.
Скрипт разворачивает её во временную базу, сравнивает количество записей с
боевой и удаляет временную базу за собой. **Боевую базу он не трогает.**

```bash
cd /home/deploy/codegolf-arena && bash scripts/verify-backup.sh
```

Ожидаемый результат — таблица, где числа «боевая» и «из копии» совпадают или
в копии чуть меньше (если после снятия копии кто-то успел что-то решить).
Делайте эту проверку раз в месяц, иначе однажды выяснится, что копии пустые.

## Проверить настройки сервера

Показывает, все ли переменные на месте и нет ли опасных значений.
Пароли выводятся замаскированными, вывод можно кому-то переслать.

```bash
cd /home/deploy/codegolf-arena && bash scripts/check-env.sh
```

## Восстановление: данные пропали или испорчены

1. **Остановить сайт**, чтобы никто не писал в базу во время восстановления:

```bash
sudo systemctl stop codegolf
```

2. **Выбрать копию** (список от старых к новым):

```bash
ls -lh /home/deploy/backups/
```

3. **Восстановить.** Скрипт сначала сам сохранит текущее состояние в
   `pre-restore-*.dump` — то есть даже неудачное восстановление можно откатить:

```bash
cd /home/deploy/codegolf-arena
bash scripts/restore-db.sh /home/deploy/backups/codegolf-ГГГГММДД-ЧЧММСС.dump --yes-overwrite
```

4. **Запустить сайт и проверить:**

```bash
sudo systemctl start codegolf
curl -fsS https://codegolf.ru/api/health && echo
```

Если восстановились не той копией — вернитесь к аварийному снимку той же
командой, указав файл `pre-restore-*.dump`.

## Настройки сервера (`.env`)

Файла `.env` нет в git — и это правильно, в нём пароли. Но значит, при потере
сервера он пропадёт вместе с ним, а без него сайт не поднять.

Что сделать один раз:

1. Открыть файл: `cat /home/deploy/codegolf-arena/.env`
2. Скопировать содержимое в менеджер паролей (Bitwarden, 1Password, KeePass) —
   отдельной записью «codegolf.ru .env».
3. Закрыть файл от посторонних: `chmod 600 /home/deploy/codegolf-arena/.env`

Обновлять эту запись каждый раз, когда меняете настройки на сервере.

## Копии вне сервера (важно)

Всё описанное выше лежит на том же сервере, что и база. Если умрёт диск —
умрёт и база, и копии. Поэтому каждую ночь, сразу после локальной копии,
скрипт `scripts/backup-offsite.sh` шифрует её паролем (AES-256) и отправляет
во внешнее S3-хранилище. В копии есть e-mail и хеши паролей участников —
поэтому в хранилище она лежит только зашифрованной.

Пока хранилище не настроено, ночная копия всё равно делается, а скрипт
просто сообщает, что наружу она не отправлена.

### Настройка (один раз)

**1. Хранилище.** В панели Timeweb: «Хранилище S3» → создать бакет,
тип **приватный**. В настройках бакета найдите адрес (endpoint), имя бакета,
Access key и Secret key.

**2. rclone на сервере** (от root):

```bash
apt install -y rclone
```

**3. Файл настроек** (от `deploy`). Команда спросит данные хранилища — секрет
вводится скрытно — и сама сгенерирует пароль шифрования:

```bash
mkdir -p ~/.config/codegolf && chmod 700 ~/.config/codegolf && read -rp "S3 endpoint (https://...): " S3E && read -rp "Имя бакета: " S3B && read -rp "Access key: " S3A && read -rsp "Secret key: " S3S && echo && PASS="$(openssl rand -base64 32)" && cat > ~/.config/codegolf/offsite.env <<EOF
S3_ENDPOINT="$S3E"
S3_REGION="ru-1"
S3_BUCKET="$S3B"
S3_ACCESS_KEY="$S3A"
S3_SECRET_KEY="$S3S"
S3_PREFIX="codegolf"
BACKUP_PASSPHRASE="$PASS"
OFFSITE_KEEP_DAYS="30"
HEALTHCHECK_URL=""
EOF
chmod 600 ~/.config/codegolf/offsite.env && unset S3S && echo && echo "СОХРАНИТЕ В МЕНЕДЖЕР ПАРОЛЕЙ, иначе копии не прочитать:" && echo "  пароль шифрования копий: $PASS" && unset PASS
```

> ⚠️ **Пароль шифрования — единственный ключ к копиям.** Если он есть только
> на сервере, то в день, когда сервер умрёт, вместе с ним умрёт и возможность
> прочитать копии. Сохраните его в менеджер паролей сразу. Туда же — весь
> файл `~/.config/codegolf/offsite.env`: на новом сервере он понадобится целиком.

Если в панели Timeweb у бакета указан регион не `ru-1` — поправьте строку
`S3_REGION` в файле.

**4. Проверка:**

```bash
cd ~/codegolf-arena && bash scripts/backup-offsite.sh
```

Должно закончиться словами «Готово: копия лежит вне сервера». Скрипт сверяет
размер файла в хранилище с отправленным, так что «Готово» означает, что копия
действительно доехала. Копии старше 30 дней из хранилища удаляются сами.

### Восстановление из хранилища

В худший день — на новом сервере, куда вы вернули `offsite.env` из менеджера паролей:

```bash
cd ~/codegolf-arena && bash scripts/fetch-offsite-backup.sh
```

Скрипт скачает самую свежую копию, расшифрует и проверит её, а в конце
напишет готовую команду восстановления. Конкретную копию можно указать
по имени: `bash scripts/fetch-offsite-backup.sh codegolf-20260918-033000.dump.gpg`.

## Мониторинг: узнать о беде раньше пользователей

Два бесплатных сторожа, оба настраиваются в браузере за пять минут.

### Сайт — UptimeRobot

**https://uptimerobot.com** → New Monitor:

- тип **HTTP(s)**, адрес `https://codegolf.ru/api/health`;
- интервал 5 минут;
- в Alert Contacts — почта, при желании Telegram.

Адрес именно `/api/health`, а не главная страница: он отвечает ошибкой не
только когда сайт лежит, но и когда отвалилась база или раннер кода.
Главная в этом случае продолжала бы открываться, а решения — не проверяться.

### Бэкапы — Healthchecks.io

**https://healthchecks.io** → Add Check:

- Period — **1 day**, Grace — **2 hours**;
- скопируйте адрес проверки (`https://hc-ping.com/...`) и впишите его
  в `~/.config/codegolf/offsite.env` в строку `HEALTHCHECK_URL`.

Теперь ночной бэкап сам отмечается после успешной отправки в хранилище.
Если копия не отправилась или бэкап вообще не запустился — придёт письмо.

---

## Чего делать нельзя

- Не восстанавливать базу, не остановив сайт — получите смесь старых и новых данных.
- Не держать копии только на боевом сервере.
- Не класть `.env` в git, даже в приватный репозиторий.
- Не доверять копии, которую ни разу не разворачивали.
