# Проба C# на арене

_План составлен и реализован 22 сентября 2026. **Выложено на codegolf.ru
и включено 22 сентября** — как это прошло, в разделе 6._

Это **проба**: C# на боевом сайте малой кровью — посмотреть, играют ли в него,
и только потом решать про полноценную мультиязычность. Разбор «во что обходится
второй язык» — в [plan.md](plan.md), этап 8.

---

## 1. Что получает игрок

- У 12 задач в списке — метка **«+ C#»**, на странице задачи — переключатель
  `[ Python ] [ C# проба ]`. Ссылка с `?lang=csharp` открывает сразу C#.
- На C# пишется **только выражение**, как на Python. Сайт показывает обёртку
  и считает длину того, что внутри:

  ```
  static int Solution(string s) => [ s.Count("aeiou".Contains) ] ;
                                     ^^^^^^^^^^^^^^^^^^^^^^^^^
                                     25 символов
  ```

- «Проверить на сервере» — прогон на открытых тестах (для C# нет проверки
  в браузере, как Pyodide у Python). «Отправить в рейтинг C#» — полная проверка,
  включая скрытые тесты.
- У C# **своя таблица рекордов**. Код чужих решений виден тем, кто сам решил
  задачу на C#, — по тем же правилам, что у Python.
- C# идёт **вне зачёта**: очков нет, в общий рейтинг, соревнования и задачу
  недели не попадает.

Всё включается и выключается одной настройкой `CSHARP_ENABLED` в `.env`.
Выключено — сайт выглядит ровно как раньше.

**Как поймём, что получилось.** Через две недели после включения смотрим:
сколько человек отправили хоть одно решение на C#, сколько — больше одного,
сколько вернулись и укоротили своё. Если первое меньше пяти — выключаем.

## 2. Принятые решения и почему

**2.1. Раннер — mono 6.12 в том же Piston.** Piston умеет только `mono 6.12.0`
и `dotnet 5.0.201`; dotnet — полный SDK и в лимиты раннера (512 МБ, полядра)
не влезает. Внутри mono — Roslyn 3.9, то есть **C# 9**: LINQ, лямбды,
`switch`-выражения, `a[^1]`, `a[1..]`, `new(){...}`, `out var`. Не работают
только `a.Order()` (.NET 7) и `[1,2,3]` (C# 12). Современный .NET — это свой
пакет для раннера, отдельная работа, если C# приживётся.

**2.2. C# хранится в своих таблицах** — `language_submissions` и
`language_best_submissions`, а не в питоновских с пометкой языка. Результаты
Python считаются примерно в 25 местах: очки, общий рейтинг, профили, главная,
соревнования, задача недели. С общими таблицами пришлось бы править каждое, и
любое пропущенное тихо подмешало бы C# в питоновский зачёт. С отдельными —
ни один существующий запрос не меняется, и C# туда не попадёт физически.
Миграция только добавляет новое; если проба не пойдёт, таблицы удаляются.

**2.3. В программе на C# нет данных тестов вообще.** Выяснили на боевом раннере:
решение **может прочитать собственный исходник с диска**. Поэтому:

- ожидаемые ответы в программу не передаются — она печатает, что вернуло
  решение, а сравнивает сервер;
- аргументы тестов приходят через стандартный ввод, и программа вычитывает его
  целиком до первого вызова решения;
- маркер блока результатов случайный и тоже приходит через ввод — решение не
  может напечатать поддельный результат;
- все служебные функции спрятаны внутри `Main`, из решения их не видно.

Список запрещённых слов (`System.`, `Console`, `Environment`, рефлексия, `Main`,
`;`, комментарии, `\u`-последовательности…) — второй слой, а не основной.

**2.4. Ответ печатается как у Python.** Ожидаемые ответы в базе записаны
по-питоновски: `[1, 2, 3]`, `['a', 'b']`, `True`, `3.0`. Программа на C# печатает
так же — массивы, вложенные списки, строки в кавычках внутри списков, словари,
`None`, дробные числа в самой короткой записи (как `repr` в Python).

**2.5. Типы — вручную, в `prisma/csharp-signatures.json`.** Имена аргументов те
же, что у Python, чтобы условие читалось одинаково. Скрипт `db:tasks:csharp`
перед записью проверяет, что **каждый** тест задачи, включая скрытые, укладывается
в объявленные типы. Из 115 задач 102 ложатся на типы C# без натяжек.

**2.6. Питоновская часть не тронута.** Для C# — своя форма на странице задачи
(`CsharpTaskView.tsx`), питоновская `SubmitForm.tsx` не менялась.

## 3. Задачи пробы

| Задача | C#-сигнатура | Скрытых тестов на сайте |
|---|---|---|
| `string-len` | `int Solution(string s)` | 1 из 4 |
| `product` | `int Solution(int[] nums)` | 1 из 4 |
| `average` | `double Solution(int[] nums)` | 2 из 5 |
| `unique-sorted` | `int[] Solution(int[] lst)` | 2 из 5 |
| `split-string` | `string[] Solution(string s, string sep)` | 2 из 5 |
| `join-strings` | `string Solution(string[] lst, string sep)` | 2 из 5 |
| `transpose-matrix` | `int[][] Solution(int[][] m)` | 5 из 8 |
| `decimal-to-binary` | `string Solution(int n)` | 9 из 12 |
| `binary-to-decimal` | `int Solution(string s)` | 9 из 12 |
| `count-vowels` | `int Solution(string s)` | 12 из 15 |
| `is-anagram` | `bool Solution(string a, string b)` | 13 из 16 |
| `is-palindrome` | `bool Solution(string s)` | 15 из 18 |

`gcd` и `lcm` из первоначального списка заменены на `binary-to-decimal` и
`count-vowels`: в .NET нет готового `gcd`, и решения раздувались до 77–87
символов — играть в такое неинтересно. Все 12 задач проверены эталонными
решениями на C# по всем тестам (эталоны в репозиторий не кладём — он публичный).

Добавить задачу в пробу — строка в `prisma/csharp-signatures.json`, дальше
деплой сам проставит сигнатуру.

## 5. Нагрузка и сервер

Замерено на боевом сервере 22 сентября:

| Что | Время |
|---|---|
| Отправка на Python | 0,13–0,26 с |
| Отправка на C#, задача со всеми тестами | 3,0–4,2 с |
| — из них компиляция (Roslyn) | 2,87 с |
| — из них запуск готовой программы | 0,10 с |

Почти всё время — компиляция; число тестов на него почти не влияет. Раннеру
отдано полядра, и компилятор на этом теряет ровно вдвое. Одновременно
собирается не больше одного C#-решения (`CSHARP_MAX_CONCURRENT=1`): две сборки
на полядра шли бы каждая вдвое дольше. Черновые проверки при длинной очереди
получают «занято, попробуйте через минуту», отправки в рейтинг ждут своей очереди.
Черновая проверка C# ограничена 12 разами в минуту с одного адреса.

Что мерить в первую неделю:

| Показатель | Норма | Тревога |
|---|---|---|
| Время от «Отправить» до результата на C# | до 5 с | стабильно больше 8 с |
| `uptime` — средняя загрузка | до 1,0 | стабильно выше 2,0 |
| `free -m` — свободно | больше 300 МБ | уходит в подкачку |
| Ошибки «раннер недоступен» / «занято» | нет | появляются |

Если тревога — по возрастанию цены:

1. **Сервер 2 ядра / 4 ГБ** в панели Timeweb, затем в `docker-compose.yml`
   раннеру `cpus: 1.0` и в `.env` `CSHARP_MAX_CONCURRENT="2"`. Отправка на C#
   укладывается примерно в 1,5 с, раннер и сайт не мешают друг другу.
2. Если апгрейд нежелателен — перевести пакет раннера на компилятор `mcs`:
   ~1,3 с без апгрейда, но язык падает до C# 7 (пропадают `switch`-выражения
   и диапазоны). Правка пакета теряется при его переустановке.
3. Если C# станет основным — вынести раннер на отдельный сервер
   (уже записано в [plan.md](plan.md) как решение владельца).

## 6. Выкладка

mono на боевом раннере **уже стоит** (поставлен 22 сентября, занял 0,8 ГБ).

1. Влить ветку `feature/csharp-trial` в `main` и запушить.
2. На сервере, под `deploy`, обычный деплой — миграция и сигнатуры применятся сами:

   ```bash
   cd ~/codegolf-arena && bash scripts/backup-db.sh && bash scripts/deploy-standalone.sh
   ```

   В выводе должно быть `C#-сигнатуры: записано 12, уже были 0, с ошибками 0`.
   **C# при этом ещё выключен** — сайт выглядит как раньше.
3. Проверить раннер и C# на сервере:

   ```bash
   cd ~/codegolf-arena && npm run test:sandbox:csharp
   ```

   Ожидаемо: `Всего проверок: 88, провалено: 0`.
4. Включить C#: в `~/codegolf-arena/.env` строка `CSHARP_ENABLED="true"`, затем:

   ```bash
   sudo systemctl restart codegolf
   ```

5. Проверить вживую: `https://codegolf.ru/api/health` показывает
   `"csharpEnabled":true` и `"csharpVersion":"6.12.0"`; в списке задач метки
   «+ C#»; на `count-vowels` переключатель, правильное решение проходит,
   `s.Length` — нет; питоновский лидерборд задачи не изменился.

**Как прошло 22 сентября.** Деплой — без ошибок, миграция применилась.
Шаг с сигнатурами в первый раз не сработал: скрипт деплоя обновляет сам себя,
но выполняется его старая версия (записано в грабли `AGENTS.md`), поэтому
`npm run db:tasks:csharp` запущен вручную — 12 из 12, по боевым тестам, включая
скрытые. На сервере: `test:sandbox` 34/34, `test:sandbox:csharp` 88/88 на боевом
mono. После включения снаружи: `/api/health` — `csharpEnabled: true`, 12 меток
«+ C#», раздел в правилах, верное решение проходит, неверное и запрещённое —
нет, питоновский лидерборд не изменился. Копия `.env` до включения —
`~/.env.before-csharp` на сервере.

**Откат** — `CSHARP_ENABLED="false"` и перезапуск службы. Код и данные
остаются, ничего не теряется. Полное удаление пробы — отдельная миграция,
удаляющая две таблицы и колонку `csharp_signature`.

## 8. Что проверили на боевом раннере до начала работы

**Установка.** Пакет `mono 6.12.0` встал за 42 секунды и занял 0,8 ГБ (пакеты
раннера выросли с 1,8 до 2,6 ГБ, на диске осталось 8,0 ГБ). В раннере появились
языки `csharp` (псевдонимы `mono`, `cs`, `c#`) и `basic` (Visual Basic, приходит
в том же пакете, не используется). Удалить, если понадобится:

```bash
curl -s -X DELETE http://127.0.0.1:2000/api/v2/packages -H "Content-Type: application/json" -d '{"language":"mono","version":"6.12.0"}'
```

**Две особенности mono**, из-за которых в коде есть специальная обработка:

- ошибки компиляции приходят в `compile.stdout`, а не в `compile.stderr`;
  прежний `piston.ts` читал только `stderr` и показал бы игроку пустое
  «Compilation error»;
- формат `"R"` печатает `1.0/3` как `0.33333333333333331` (17 цифр), а Python —
  `0.3333333333333333`. Поэтому дробные печатаются с подбором самой короткой
  точной записи (15, 16 или 17 цифр).

**Подтверждено, что решение видит файлы рядом:** `System.IO.Directory.GetFiles(".")`
вернул `./main.cs.cs,./out`. Отсюда решение 2.3.
